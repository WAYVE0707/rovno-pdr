# Смена ниши: что переделывать, а что остаётся

Кодовая база не привязана к PDR жёстко. PDR живёт в четырёх местах, всё остальное — универсальный движок.

## Меняется под новую нишу

1. `presets/<ниша>.json` — вопросы калькулятора, прайс, коэффициенты, правила-блокировки, тексты-дисклеймеры.
2. `src/pages/Home.tsx` — тексты лендинга (заголовок, «как это работает», отзывы, FAQ).
3. `src/components/CarMap.tsx` — визуальный выбор зоны (у мебели/интерьера будет свой SVG вместо машины).
4. Мелочи: `renderIndex()` в `server/index.mjs` (title/og «ремонт вмятин без покраски»), тексты бота в `server/bot.mjs`, `docs/`.

## Остаётся как есть (переиспользуется целиком)

- Движок расчёта: `src/lib/calc.ts` (шаги → цена, модификаторы, правила).
- Приём заявок: `/api/leads`, фото, `data/leads.json`.
- Админка: заявки, статусы, прайс, фото работ, генератор демо-ссылки.
- Telegram-бот: уведомления и команды.
- Виджет на чужой сайт: `/w.js`, `/embed/:id`, `data/embeds.json`.
- Демо-ссылки с подменой бренда (`?b&c&p`), OG-превью, деплой (`deploy/install.sh`), Render.

## Чек-лист новой ниши (60–90 минут)

1. Скопировать `presets/pdr.json` → `presets/<ниша>.json`, переписать шаги:
   - `steps[]` — что спрашиваем (зона, размер, тип, срочность);
   - `base_rates` — прайс-матрица;
   - `modifiers` — доплаты (демонтаж, выезд, срочность);
   - `rules[]` — когда не считаем и просим осмотр;
   - `copy` — формулировки для клиента.
2. Переписать тексты `Home.tsx` под нишу (что продаём, кому, почему выгодно).
3. Заменить `CarMap` на схему ниши (комната, изделие, объект) или убрать.
4. Проверить `renderIndex` и `bot.mjs` — там зашито «ремонт вмятин».
5. `npm run build` → локальная проверка → демо-ссылка → отправка.

## Что важно понимать про продажи

Сайт — не узкое место. Узкое место — трафик и доверие:
- в PDR мастер отвечает на вопрос «сколько стоит», поэтому ему можно продать расчёт;
- в нише, где клиент платит процент за приведённого человека, продукт — не сайт, а **лид**: лендинг + кнопка звонка + учёт, откуда пришёл звонок.
