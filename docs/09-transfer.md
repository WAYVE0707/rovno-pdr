# 09. Перенос сайта с твоего сервера на сервер клиента

Схема продажи: **сайт живёт у тебя месяц, потом переносится клиенту** — и обязательства
заканчиваются. Подписки нет: дальше клиент платит хостеру и регистратору напрямую.
Ниже — процедура переноса, чтобы это занимало 30–40 минут и не теряло заявки.

## Что переносится

| Что | Где лежит | Как переносится |
|---|---|---|
| Код сайта | GitHub `WAYVE0707/rovno-pdr` | `git clone` на новом сервере |
| Заявки | `data/leads.json` | архивом |
| Настройки (бренд, прайс, chat_id) | `data/settings.json` | архивом |
| Фото работ мастера | `data/works/w1…w6.jpg` | архивом |
| Фото из заявок | `data/photos/` | архивом |
| `.env` | не в git | создаётся заново (токен бота тот же) |
| Домен | reg.ru | смена A-записи на новый IP |
| Бот | у клиента | не трогаем, токен тот же |

## Подготовка (за неделю до переноса)

1. Понизить TTL домена до 300 секунд — иначе после смены IP часть клиентов будет видеть
   старый сервер до 24 часов.
2. Напомнить клиенту: «через месяц хостинг переходит на вас — зарегистрируйте Beget
   и домен, это 10 минут».

## День переноса

**Клиент делает (10 минут):**
1. beget.com → регистрация на своё имя, телефон, карта.
2. Создать VPS «1 core 1 GB», Ubuntu 24.04 → прислать IP и root-пароль.
3. Домен: если покупали на его имя — просто дать доступ к DNS; если домен на тебе —
   оформить перенос администратора домена.

**Ты делаешь (30–40 минут):**

```bash
# 1. Архив данных на старом сервере
cd /opt/rovno && tar czf /tmp/rovno-data.tgz data/
scp /tmp/rovno-data.tgz root@НОВЫЙ_IP:/tmp/

# 2. Новый сервер: ставим окружение
ssh root@НОВЫЙ_IP
apt update && apt install -y nodejs npm caddy git
git clone https://github.com/WAYVE0707/rovno-pdr.git /opt/rovno
cd /opt/rovno && npm ci && npm run build

# 3. Данные
mkdir -p /opt/rovno/data && tar xzf /tmp/rovno-data.tgz -C /opt/rovno

# 4. .env — новый ADMIN_PASSWORD, тот же TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
nano /opt/rovno/.env
# PORT=8787
# ADMIN_PASSWORD=<новый, 12+ символов>
# TOKEN_SECRET=<новый случайный>
# TELEGRAM_BOT_TOKEN=<тот же>
# TELEGRAM_CHAT_ID=<тот же>
# PUBLIC_URL=https://домен
# BOT_POLLING=1

# 5. systemd + Caddy
cp deploy/rovno.service /etc/systemd/system/ && systemctl enable --now rovno
# /etc/caddy/Caddyfile: домен { reverse_proxy 127.0.0.1:8787 }
systemctl reload caddy
curl -s localhost:8787/api/health
```

**Переключение домена:**
1. В DNS поменять A-запись на новый IP.
2. Подождать 5–10 минут, проверить `dig домен +short`.
3. Проверить: сайт открывается, HTTPS-замок, калькулятор считает, заявка пришла в бота.

**Закрытие:**
1. Клиент меняет root-пароль и присылает подтверждение, что зашёл.
2. Старый сервер: `systemctl stop rovno`, через сутки удалить VPS.
3. В `data/clients.csv` отметить: `renew_at` = дата окончания, `note` = «перенесён на клиента».
4. Бот оставить включённым на старом сервере до переключения DNS, потом выключить —
   иначе два сервера будут драться за long polling (ошибка 409).

## Если клиент не отвечает и не переносится

1. За 7 дней до конца — сообщение: «хостинг заканчивается 12 марта, перевожу на вас:
   регистрируете Beget и домен, присылаете IP — дальше платите напрямую, около 400 ₽/мес.
   Если не нужно, скажите, выключу».
2. Нет ответа → за 3 дня второе сообщение, коротко: «выключаю 12 марта?».
3. Дата прошла → сайт выключается (`systemctl stop rovno`), данные хранятся 90 дней.
4. Данные клиента (заявки, фото) по запросу отдаются архивом. Через 90 дней — удаляются.

Продлевать за свой счёт нельзя: это единственная статья, где схема начинает терять деньги.

## Если клиент забирает сайт (не переносит)

Он имеет право просто забрать результат и разбираться сам. Отдаёшь архив и выключаешь сервер:

```bash
cd /opt/rovno
tar czf /tmp/rovno-site-КЛИЕНТ.tgz --exclude=node_modules --exclude=.git .
ls -lh /tmp/rovno-site-КЛИЕНТ.tgz     # обычно 2–5 МБ
```

В архиве: код, `data/` (заявки, настройки, фото работ и фото заявок), `docs/`.
Чего в архиве нет и что клиенту нужно получить отдельно: токен бота (у него уже есть — бот его),
пароль админки (тот, что выдал), домен (переоформляешь, если просит).

Отправить архив в чат, написать: «сайт у вас, дальше размещаете где удобно — я в этом
не участвую». Сервер выключаешь, данные на нём удаляешь через 90 дней.

## Переиспользование сервера под следующего клиента

Сервер уже настроен — это главная ценность схемы. Что сделать (15 минут):

```bash
cd /opt/rovno
rm -rf data/leads.json data/photos data/works   # данные прошлого клиента — обязательно
git pull && npm ci && npm run build
# новый .env: новый ADMIN_PASSWORD, новый токен бота, новый chat_id
systemctl restart rovno
```

Дальше в `/admin`: название, город, телефон, прайс, фото работ. Домен — новый (старый ушёл
клиенту или удаляется).

**Правило:** никогда не отдавать новому клиенту сервер с данными предыдущего. Всегда `rm -rf data/`
и новый токен бота.
